# 浮点数值断言：IEEE754 下 0.08 * 5 ≠ 0.4

- 类别：pitfalls
- 入库条件：④ 可重复解决方法 + ⑤ 容易再次踩中的坑
- 日期：2026-08-13

## 现象

R2-03D 黄金样例：`fatigue + move_speed * fatigue_rate * dt`，期望 10.4。若用：

```ts
expect(result).toBe(10.4); // ❌ 失败
```

实际得到 `10.40000000000000036`（0.08 在二进制下非精确，×5 后误差累积）。XYLab 是数值模拟工具，此后每一轮（Tick 结算、统计、图表）都会遇到浮点误差。

## 根因

IEEE754 双精度浮点：十进制小数如 0.08、0.1 无法精确表示，运算误差必然存在。`toBe` 是精确相等（Object.is），对浮点结果几乎必挂。

## 正确做法

数值断言统一使用：

```ts
expect(result).toBeCloseTo(10.4, 10); // 精度位数按场景定
```

整数/精确可表示的结果（如 15、-5、0）仍可用 `toBe`。

## 禁止

- ❌ `expect(x).toBe(0.3)` 类精确断言浮点结果。
- ❌ 在业务代码里对浮点做 `===` 比较再「修正」误差——运行时语义保持 IEEE754，测试层负责容差。

## 验证方式

黄金样例 D36（疲劳公式 → 10.4）用 `toBeCloseTo(10.4, 10)` 全绿；同一测试用 `toBe` 会稳定失败，可即时复现本坑。
